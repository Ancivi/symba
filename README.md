# SYMBA

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.24376948.svg)](https://doi.org/10.5281/zenodo.24376948)

Code for the paper *Higher-order functional networks from event time series*, by
A. Civilini, F. de Vico Fallani and V. Latora (see [How to cite](#how-to-cite)).

SYMBA (SYMbolic BAyesian) infers higher-order functional networks from multivariate event
time series, such as the spikes of neurons, the price changes of stocks or the emails sent
by the employees of a company. It works in three steps:

1. **From events to symbols.** Each unit is associated with a symbol. Events that follow
   each other within a time window Δt are placed in adjacent positions of a symbolic
   sequence, and a space symbol is inserted when no event occurs within Δt.
2. **Significance of the tuples.** For each tuple of k adjacent symbols (ordered or
   unordered), SYMBA tests the null hypothesis that the sequence is generated by a
   stationary Markov process of order k − 2, so that the probability of the tuple is
   explained by those of its shorter sub-tuples. It builds a Beta prior from the expected
   probability of the tuple under this null model and a Beta posterior from its observed
   number of occurrences, and scores the tuple by the Jensen–Shannon distance between the
   two (BJS score).
3. **Hypergraph.** The tuples with a BJS score above a threshold (0.6 in the paper) are the
   motifs, and they define the hyperedges of a hypergraph whose nodes are the units.

SYMBA does not require a model of the underlying dynamics, and its computational cost grows
linearly with the length of the sequence. The inferred hyperedges encode statistical
(functional) dependencies, which may also reflect indirect effects or the temporal overlap
of events, rather than direct physical interactions.

The repository contains the method (`src/symba/`) and the notebooks that reproduce the
analyses and figures of the paper and of its Supplemental Material, including the
comparison with shuffle-based (p-value, z-score) and batch z-score methods.

## Installation

From the repository root:

```bash
pip install -r requirements.txt
pip install -e .
```

`requirements.txt` pins the versions the code was tested with (Python 3.14).
`pip install -e .` alone installs the package with unpinned dependencies; add the `stock`
extra (`pip install -e ".[stock]"`) for the stock-market case study, which needs `yfinance`.
The notebooks also work without installing the package: their first cell adds `src/` to
the Python path and moves to the repository root, whether they are opened from
`notebooks/` or from the root.

The brain preprocessing notebook needs a separate environment (Python 3.11, `allensdk`),
which conflicts with the one above: see [Brain data](#brain-data).

## Reproducing the analyses

Run `notebooks/demo_and_figures.ipynb` from top to bottom. It reproduces the figures of the
main text and a selection of the supplementary ones, as worked examples of the method
(figures combining several panels were assembled from the individual plots). With the
default settings this takes about 10 minutes: the long simulations are not rerun, and their
figures are made from the results shipped in `data/`. Figures are saved to `outputs/figures/`.

| Notebook section | Data | Rerun the simulations with | Time |
|---|---|---|---|
| Robustness to symbol noise (substitution and deletion) | `data/aggregated_results_*` | `RECOMPUTE_NOISE = True` | seconds (sweep: ~20 min) |
| Convergence of the shuffle null model to the analytical expected probability | computed | — | ~3 min |
| Data-sparse and noise-dominated regimes: thresholds of the noise-to-signal ratio | computed | — | seconds |
| Classification performance: SYMBA vs shuffle (p-value, z-score) vs batch z-score | `data/four_methods_summary_*` | `RECOMPUTE_FOUR_METHODS = True` | seconds (sweep: several hours) |
| Counting baseline for ordered 4-tuples | computed | — | ~30 s |
| Detections at fixed significance thresholds (SYMBA > 0.6; shuffle p-value < 0.05, Bonferroni, Benjamini–Hochberg) | `data/four_methods_thresholded_*` | `RECOMPUTE_THRESHOLDED = True` (needs the complete results, see `data/README.md`) | seconds |
| Choosing the BJS threshold from shuffled sequences | computed | — | ~20 s |
| Markov-generated sequences, and decay of their correlations | `data/markovsequences/` | `RECOMPUTE_MARKOV = True` | seconds |
| Stock market (unsigned and signed) | downloaded from Yahoo Finance at run time | — | ~2 min |
| Enron emails | `data/emails.csv` (Kaggle, see `data/README.md`) | — | ~2 min |
| Brain areas (Allen Institute Neuropixels) | `data/sequences_session29_…_brainareas_multinomial.csv` | — | ~1.5 min |

`RECOMPUTE = True` in the first cell reruns every simulation.

The brain section analyses 100,000 consecutive spikes of the recording, to keep the comparison with the shuffle
method feasible in time; the significant tuples reported in the paper are computed on the whole sequence
(about 40 million spikes), in the last cell of that section.

In the stock-market section, an event is recorded for a stock on every day its closing price changes by more
than 2% (unsigned), or separately for rises and drops (signed).

### Reproducibility

- All random steps (synthetic sequences, noise, shuffles, and the order of events that occur
  at the same time) are seeded with `SEED` in the first cell, so the same data and seed give
  the same results. The results in the paper were obtained before seeding was added, so they
  are reproduced statistically, not digit for digit.
- The stock prices are downloaded when the notebook runs; the results in the paper use the download of
  2 October 2026. Yahoo Finance occasionally revises historical data, and events on the same day are put in
  random order, so with a later download the number of significant tuples can vary slightly; the strongest
  motifs are stable.
- Enron emails: each email is counted once (the dataset stores copies of the same email in
  several folders of the sender's mailbox) and ordered by its timestamp.

## Brain data

`notebooks/brain_neuropixel_preprocessing.ipynb` builds the brain-area symbolic sequence
used by the brain section from the Allen Institute Neuropixels Visual Coding data:

1. Set up its environment: `./setup_brain_preprocessing_env.sh` (conda instructions in the
   script header). It pins `pynwb`/`hdmf` versions that can read the Allen Institute files.
2. Set `ALLOW_DOWNLOAD = True` in the notebook's setup cell and run it once to download the
   metadata and the session used in the paper (~2.5 GB, not the whole ~130 GB dataset); then
   set it back to `False`.
3. Run the notebook.

Details, and a known AllenSDK issue this setup protects against, are in `data/README.md`.

## Using SYMBA on your own data

```python
import symba

# From timestamped events: a pandas DataFrame indexed by event time, with a 'unit_id'
# column. The space symbol (-1) is inserted when two consecutive events are more than
# time_bin (the time window Δt) apart.
sequence, times = symba.events_to_symbolic_sequences(time_bin, events, spacebar=1)
# Or directly: sequence = [...] (ints or strings, -1 for gaps); times = list(range(len(sequence)))

quantiles = [0.01] + [round(0.05 * k, 2) for k in range(1, 20)] + [0.99]  # as in the notebook
observed, expected = symba.observed_counts_and_expected_probs(
    sequence, times, max_size=3, ordered_words=0)   # ordered_words=1: order within a motif matters
scores = symba.js_score_per_size(
    sequence, observed, expected, max_size=3, quantiles_list=quantiles)

significant_pairs = {t: s for t, s in scores[2].items() if s > 0.6}
```

`scores[k]` maps each over-represented tuple of length `k` to its BJS score, which ranges
from 0 to about 0.83. The paper uses the threshold 0.6 (see its Supplemental Material on the
choice of the threshold). The threshold of each tuple length can also be estimated from
shuffled copies of the sequence, which satisfy the null model of SYMBA (about ten are enough):

```python
shuffled = symba.shuffled_js_scores(sequence, max_size=3, n_shuffles=10, ordered_words=0)
conservative = symba.bjs_threshold_percentile(sequence, max_size=3, shuffled_scores=shuffled)
fdr = symba.bjs_threshold_fdr(scores, sequence, max_size=3, ordered_words=0,
                              shuffled_scores=shuffled)
```

`bjs_threshold_percentile` returns, for each tuple length, the 95th percentile of the maximum
score in the shuffled sequences (about 5% probability of reporting even one false positive).
`bjs_threshold_fdr` returns the smallest threshold for which the false positives are expected
to be at most 5% of the detected tuples (false discovery rate), which detects more motifs at
the cost of a few false positives. It returns `nan` for a tuple length at which no threshold
reaches this rate, for instance when the sequence contains no motifs of that length.
